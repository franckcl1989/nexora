# 工程演进原则

项目是长期演进型 GUI 产品（Rust / Tauri / WASM / AI），设计随使用逐步清晰，
走小步快跑、快速迭代路线。本文件是与 AGENTS.md 互补的工程演进约束，适用于所有代理。

## 1. 小步快跑，同时保持演进质量
- 每次只做能尽快交付、可验证的一小步；不等待一次性设计完美。
- 但每完成一个原子改动，执行一次演进评估：
  - 是否有可合并的重复代码、可收敛的抽象、可简化的层次？
  - 是否有现在调整能让下一步更顺畅的架构点？
  - 是否引入了会阻碍未来演进的临时结构？
- 禁止堆屎山：不得引入 dead code、临时 adapter、compatibility shim、dual path、
  无意义 feature flag、TODO 式架构。
- 发现根本设计错误时修正正确边界，而不是在小 diff 上继续叠加错误架构。

## 2. 依赖边界面向 trait，可替换优先
- 大技术方向已定，但具体依赖与组件未来可能被替换
  （AI provider、存储、平台能力、WASM runtime、前端框架等）。
- 凡与易变依赖相接的边界，默认定义 trait 表达产品能力契约，实现方为可替换 adapter；
  替换依赖时改动只落在对应 adapter 内，产品语义与调用方不受影响。
- 领域内部遵循 AGENTS.md 的 concrete type 优先；trait 只用于真实多实现、
  真实替换风险或共享行为契约的边界，禁止无抽象价值的接口分层。
- 不为尚未发生的替换过度设计：边界薄、语义清晰即可，抽象以真实替换路径为据。
